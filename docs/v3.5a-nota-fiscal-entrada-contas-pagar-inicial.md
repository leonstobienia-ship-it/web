# V3.5A - Nota Fiscal de Entrada e Conta a Pagar Inicial ERP ENAC

## Objetivo

Implementar Nota Fiscal de Entrada vinculada a Pedido de Compra e provisionar a primeira Conta a Pagar local no PostgreSQL `enac_erp_dev`.

A etapa nao implementa programacao bancaria, pagamento, baixa financeira, conciliacao, emissao fiscal, XML, SEFAZ, prefeitura, SharePoint, Entra, automacoes ou `DELETE` fisico.

## Banco de dados

- Migration incremental: `database/migrations/008_notas_fiscais_entrada_contas_pagar_inicial.sql`.
- Tabelas usadas: `notas_fiscais_entrada`, `notas_fiscais_entrada_itens` e `contas_pagar`.
- `notas_fiscais_entrada_itens` passa a manter `nota_fiscal_id` como vinculo canonico da V3.5A, preservando `nota_id` para compatibilidade local.
- `contas_pagar.nota_fiscal_id` ja existia na fundacao apontando para `notas_fiscais`; por isso o vinculo operacional de NF de entrada continua em `nota_entrada_id`.

Status de NF:

```text
RASCUNHO
CONFERIDA
DIVERGENTE
APROVADA
PROVISIONADA
CANCELADA
```

Status de conta:

```text
PROVISIONADA
APROVADA
AGUARDANDO_PROGRAMACAO
PROGRAMADA
PAGA
CANCELADA
```

Na V3.5A somente `PROVISIONADA` e `CANCELADA` sao operacionalizados para contas. Os demais ficam reservados.

## API

Notas fiscais:

```text
GET    /notas-fiscais-entrada
GET    /notas-fiscais-entrada/:id
POST   /notas-fiscais-entrada
POST   /notas-fiscais-entrada/gerar-do-pedido
PATCH  /notas-fiscais-entrada/:id
PATCH  /notas-fiscais-entrada/:id/conferir
PATCH  /notas-fiscais-entrada/:id/marcar-divergente
PATCH  /notas-fiscais-entrada/:id/reabrir-rascunho
PATCH  /notas-fiscais-entrada/:id/aprovar
PATCH  /notas-fiscais-entrada/:id/provisionar-conta-pagar
PATCH  /notas-fiscais-entrada/:id/cancelar
```

Contas a pagar:

```text
GET    /contas-pagar
GET    /contas-pagar/:id
POST   /contas-pagar/provisionar-da-nota
```

`POST /contas-pagar/gerar-da-nota` permanece como alias local, gerando apenas conta `PROVISIONADA`.

## Fluxo

```text
Pedido EMITIDO | ENVIADO_FORNECEDOR | CONFIRMADO
  -> Nota RASCUNHO
  -> CONFERIDA
  -> APROVADA
  -> PROVISIONADA + Conta PROVISIONADA
```

Fluxo de divergencia:

```text
RASCUNHO -> DIVERGENTE -> RASCUNHO
```

Cancelamento de NF permitido em:

```text
RASCUNHO
CONFERIDA
DIVERGENTE
```

## Validador local

```powershell
cd server
npm.cmd run migrate
npm.cmd run smoke:notas
```

O smoke `smoke:notas` cria cenario `DEV_LOCAL_V3_5A`, gera NF do pedido, valida itens herdados, aprova a NF, provisiona conta a pagar, valida `GET /contas-pagar` e bloqueia duplicidade com `409`.

## Frontend

- Menu: `Notas Fiscais`.
- Tela de NF: lista, filtros, geracao a partir de pedido, detalhe, edicao de rascunho, divergencia, aprovacao, provisionamento e cancelamento.
- Tela de Contas a Pagar: lista e detalhe de contas provisionadas.
