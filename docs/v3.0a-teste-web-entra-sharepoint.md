# V3.0A - Teste web com Entra e listas SharePoint

Objetivo: testar o Sistema ENAC fora de uma webpart SPFx, mantendo a estrutura React/modelos/repositório já desenvolvida.

## O que foi preservado

- Componente principal `EnacSistema`.
- Modelos de dados em `src/webparts/enacSistema/models.ts`.
- Repositório SharePoint com mapeamento das listas reais.
- Webpart SPFx existente, para comparação e rollback.

## O que foi adicionado

- Host web em `web/` com Vite.
- Login Microsoft Entra via `@azure/msal-browser`.
- Cliente HTTP `SharePointFetchClient`, que injeta token Bearer nas chamadas REST do SharePoint.
- Contrato `IEnacRepository`, removendo o acoplamento do componente React ao SPFx.

## Configuração local

1. Copie `web/.env.example` para `web/.env.local`.
2. Preencha:
   - `VITE_ENAC_ENTRA_CLIENT_ID=0dab19b3-8e48-4f89-ad94-1446b08d3781`
   - `VITE_ENAC_ENTRA_TENANT_ID=enaccombr.onmicrosoft.com`
   - `VITE_ENAC_SHAREPOINT_SITE_URL=https://enaccombr.sharepoint.com/sites/Equipe.Obras`
3. No Microsoft Entra, registre uma SPA com redirect URI:
   - `http://localhost:5173`
   - `https://sistema-enac.netlify.app`
4. Conceda escopo delegado compatível com SharePoint REST. Por padrão o host usa:
   - `https://enaccombr.sharepoint.com/AllSites.Read`

- `VITE_ENAC_ENTRA_TENANT_ID`
- `VITE_ENAC_SHAREPOINT_SITE_URL`

Ponto externo ainda necessario no Microsoft Entra: o app registration usado no client id acima precisa aceitar `https://sistema-enac.netlify.app` como SPA redirect URI.


## Observações de segurança

- O host web nasce em modo readonly.
- As flags de escrita controlada não são habilitadas no bootstrap web.
- Para escrita futura, criar rodada própria e escopo Entra/SharePoint explícito, mantendo confirmação manual e marcadores de teste.
