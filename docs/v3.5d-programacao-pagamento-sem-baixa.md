# V3.5D - Programacao de Pagamento sem Baixa

## Escopo

A V3.5D cria o modulo local de Programacao de Pagamento para agrupar Contas a Pagar ja aprovadas, submeter o agrupamento para aprovacao por alcada e registrar a programacao como aprovada sem executar pagamento, baixa, CNAB ou integracao bancaria.

Permanece fora do escopo:

- pagamento real;
- baixa financeira;
- liberacao bancaria real;
- CNAB ou API bancaria;
- banco de producao;
- SharePoint real;
- Microsoft Entra real;
- Power Automate;
- `DELETE` fisico.

## Migration

Arquivo:

```text
database/migrations/011_programacoes_pagamento_sem_baixa_v35d.sql
```

Principais alteracoes:

- cria `programacoes_pagamento`;
- cria `programacoes_pagamento_itens`;
- adiciona `contas_pagar.ativo`;
- adiciona `contas_pagar.divergencia_pendente`;
- cria indice unico parcial para impedir a mesma conta em programacao ativa duplicada;
- cria escopos locais do modulo `programacoes-pagamento`;
- cria alcadas locais para `PROGRAMACAO_PAGAMENTO`:
  - `FINANCEIRO` aprova tecnicamente ate R$ 20.000;
  - `DIRETORIA` aprova acima de R$ 20.000.

## Status

Programacao de pagamento:

```text
RASCUNHO
SUBMETIDA
APROVADA
REPROVADA
CANCELADA
```

Itens da programacao:

```text
ATIVA
REMOVIDA
CANCELADA
```

## Elegibilidade

Uma Conta a Pagar so pode entrar em programacao quando:

- esta ativa;
- esta em status `APROVADA`;
- tem aprovacao interna `APROVADO_TECNICO` ou `APROVADO_DIRETORIA`;
- nao esta cancelada;
- nao possui divergencia pendente;
- nao esta vinculada a outra programacao ativa;
- possui valor aberto maior que zero.

A aprovacao da programacao nao altera `valor_aberto` e nao marca a conta como `PAGA`. A duplicidade de programacao e controlada pelo vinculo ativo em `programacoes_pagamento_itens`.

## Agrupamento

A programacao agrupa contas por:

- data prevista;
- fornecedor;
- obra;
- centro de custo;
- forma de pagamento prevista.

Ao adicionar a primeira conta ao rascunho, os campos de agrupamento ainda vazios sao preenchidos com os dados da conta. Novas contas precisam pertencer ao mesmo agrupamento.

## Endpoints

```text
GET   /programacoes-pagamento
GET   /programacoes-pagamento/:id
GET   /programacoes-pagamento/contas-elegiveis
POST  /programacoes-pagamento
POST  /programacoes-pagamento/:id/contas
PATCH /programacoes-pagamento/:id/contas/:contaPagarId/remover
PATCH /programacoes-pagamento/:id/submeter
PATCH /programacoes-pagamento/:id/aprovar-tecnico
PATCH /programacoes-pagamento/:id/aprovar-diretoria
PATCH /programacoes-pagamento/:id/reprovar
PATCH /programacoes-pagamento/:id/cancelar
```

Nao existem endpoints `/pagar`, `/baixar`, CNAB ou integracao bancaria.

## Auditoria

O modulo registra eventos em `auditoria_eventos` para:

- criar programacao;
- adicionar conta;
- remover conta;
- submeter;
- aprovar por alcada;
- bloquear por alcada;
- reprovar;
- cancelar.

## Frontend

A tela `Programacao de Pagamento` permite:

- listar programacoes;
- criar rascunho;
- visualizar contas elegiveis e bloqueadas;
- adicionar contas elegiveis ao rascunho;
- remover logicamente contas do rascunho;
- submeter para aprovacao;
- aprovar por alçada;
- reprovar;
- cancelar logicamente.

A tela nao exibe acao de pagar, baixar, CNAB ou integracao bancaria.

## Smoke

Comando:

```powershell
cd server
npm.cmd run smoke:programacoes-pagamento
```

O smoke usa marcador `DEV_LOCAL_V3_5D` e valida:

- conta nao aprovada bloqueada;
- conta aprovada incluida em programacao;
- duplicidade ativa bloqueada;
- submissao de programacao;
- bloqueio por alçada insuficiente;
- aprovacao da diretoria acima de R$ 20.000;
- aprovacao sem pagamento;
- aprovacao sem baixa;
- rotas `/pagar` e `/baixar` ausentes;
- `DELETE` fisico ausente.
