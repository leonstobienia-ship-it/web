# V3.6 - Medicoes e Faturamento

## Objetivo

Implementar o controle local de medicoes de obra e pedidos internos de faturamento no ERP ENAC, sem emissao fiscal real, sem prefeitura, sem boleto, sem cobranca bancaria e sem baixa automatica de recebivel.

## Escopo entregue

- Migration `016_medicoes_faturamento_v36.sql`.
- Evolucao da tabela `medicoes_obra`.
- Nova tabela `medicoes_obra_itens`.
- Nova tabela `pedidos_faturamento`.
- Endpoints REST para medicoes e pedidos de faturamento.
- Tela `Medições e Faturamento`.
- Smoke `npm.cmd run smoke:medicoes-faturamento`.
- Auditoria em `auditoria_eventos`.

## Fluxo

```text
RASCUNHO -> SUBMETIDA -> APROVADA -> FATURAMENTO_SOLICITADO -> FATURADO_MANUALMENTE
SUBMETIDA -> DEVOLVIDA -> SUBMETIDA
RASCUNHO | SUBMETIDA | DEVOLVIDA | APROVADA | FATURAMENTO_SOLICITADO -> CANCELADA
```

`FATURADO_MANUALMENTE` e apenas registro interno de que o faturamento externo foi informado. Nao emite NFS-e real.

## Endpoints

```text

GET    /medicoes/:id
POST   /medicoes
PATCH  /medicoes/:id
PATCH  /medicoes/:id/enviar

PATCH  /medicoes/:id/devolver
PATCH  /medicoes/:id/cancelar
POST   /medicoes/:id/itens
PATCH  /medicoes/:id/itens/:itemId

PATCH  /pedidos-faturamento/:id/aprovar
PATCH  /pedidos-faturamento/:id/marcar-faturado-manualmente
```

## Regras

- Medicao deve estar vinculada a obra e cliente.
- Obra e cliente devem estar ativos.
- Se a obra ja possui cliente, o cliente informado deve coincidir.
- Medicao precisa de ao menos um item ativo para ser enviada.
- Valor bruto e calculado pelos itens ativos.
- Item nao e removido fisicamente; apenas inativado.
- Pedido de faturamento so nasce de medicao `APROVADA`.
- Pedido ativo nao pode ser duplicado para a mesma medicao.
- Aprovacao usa alcadas locais de `medicoes-faturamento`.
- Registrar faturamento manual exige usuario, data e observacao.
- Medicao faturada manualmente nao pode ser cancelada nesta etapa.

## Limites

- Sem emissao real de NFS-e.
- Sem integracao com prefeitura.
- Sem boleto real.
- Sem cobranca bancaria.
- Sem integracao bancaria.
- Sem baixa automatica de recebivel.
- Sem SharePoint real.
- Sem Entra real.
- Sem Power Automate.
- Sem `DELETE` fisico.
