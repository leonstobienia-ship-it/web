# V2.X - Publicacao automatizada do pacote SPFx via PnP.PowerShell

## Objetivo

Preparar uma rotina controlada para publicar o pacote SPFx do Sistema ENAC no App Catalog sem repetir o upload manual pelo navegador.

Esta rotina publica apenas o arquivo `.sppkg`. Ela nao altera listas SharePoint, dados operacionais, permissoes funcionais, fluxos Power Automate, regras de negocio ou a interface homologada do prototipo V2.2.

## Escopo validado

- Pacote local: `C:\Users\leon\OneDrive - enac.com.br\Documentos\Sistema ENAC\sharepoint\solution\enac-sistema-spfx.sppkg`
- App Catalog: `https://enaccombr.sharepoint.com/sites/appcatalog`
- Site de homologacao: `https://enaccombr.sharepoint.com/sites/Equipe.Obras`
- Tenant: `enaccombr.onmicrosoft.com`
- ClientId publico informado para login interativo/device login.

## Script

Arquivo:

```powershell
.\scripts\sharepoint\18-publicar-pacote-spfx-pnp.ps1
```

Parametros principais:

- `Tenant`: tenant Microsoft 365.
- `ClientId`: app/client id usado pelo PnP.PowerShell.
- `AppCatalogUrl`: URL do App Catalog.
- `SiteUrl`: site onde o app deve ser instalado ou atualizado.
- `PackagePath`: caminho absoluto do `.sppkg`.
- `AuthMode`: `DeviceLogin` ou `Interactive`.
- `Execute`: habilita execucao real.
- `ConfirmacaoPublicacao`: token obrigatorio para execucao real.

Token exigido para publicacao:

```text
CONFIRMAR-PUBLICACAO-SPFX-SISTEMA-ENAC
```

## Dry-run local

O dry-run valida ambiente e pacote, gera relatorio e nao abre conexao SharePoint.

```powershell
pwsh .\scripts\sharepoint\18-publicar-pacote-spfx-pnp.ps1 `
  -Tenant "enaccombr.onmicrosoft.com" `
  -ClientId "0dab19b3-8e48-4f89-ad94-1446b08d3781" `
  -AppCatalogUrl "https://enaccombr.sharepoint.com/sites/appcatalog" `
  -SiteUrl "https://enaccombr.sharepoint.com/sites/Equipe.Obras" `
  -PackagePath "C:\Users\leon\OneDrive - enac.com.br\Documentos\Sistema ENAC\sharepoint\solution\enac-sistema-spfx.sppkg"
```

Relatorio esperado:

```text
reports/v2.x-publicacao-spfx-pnp-dryrun.md
```

## Execucao real controlada

Executar somente quando Leon autorizar explicitamente a publicacao automatizada.

```powershell
pwsh .\scripts\sharepoint\18-publicar-pacote-spfx-pnp.ps1 `
  -Tenant "enaccombr.onmicrosoft.com" `
  -ClientId "0dab19b3-8e48-4f89-ad94-1446b08d3781" `
  -AppCatalogUrl "https://enaccombr.sharepoint.com/sites/appcatalog" `
  -SiteUrl "https://enaccombr.sharepoint.com/sites/Equipe.Obras" `
  -PackagePath "C:\Users\leon\OneDrive - enac.com.br\Documentos\Sistema ENAC\sharepoint\solution\enac-sistema-spfx.sppkg" `
  -Execute `
  -ConfirmacaoPublicacao "CONFIRMAR-PUBLICACAO-SPFX-SISTEMA-ENAC"
```

Relatorio esperado:

```text
reports/v2.x-publicacao-spfx-pnp-execucao.md
```

## Comportamento esperado da execucao

1. Validar PowerShell, PnP.PowerShell e arquivo `.sppkg`.
2. Conectar ao App Catalog com login interativo ou device login.
3. Publicar/substituir o pacote com `Add-PnPApp -Overwrite -Publish`.
4. Conectar ao site de homologacao.
5. Localizar o app do Sistema ENAC.
6. Tentar atualizar o app instalado; se o comando de atualizacao nao estiver disponivel, tentar instalar/atualizar pelo comando compativel.
7. Registrar relatorio sanitizado, sem tokens ou credenciais.

## Garantias e limites

- O script nao executa escrita em listas operacionais.
- O script nao cria, altera ou remove permissoes funcionais.
- O script nao inicia nem publica Power Automate.
- O script nao registra segredos, bearer tokens ou credenciais.
- A publicacao do pacote pode exigir consentimentos/permissoes administrativas no App Catalog.
- Depois da publicacao, a pagina de homologacao ainda deve ser validada no navegador com cache novo para confirmar o novo asset SPFx carregado.

## Bloqueio observado em 2026-06-11

A execucao real autenticou no App Catalog, mas o comando `Add-PnPApp` foi recusado pelo SharePoint com:

```text
Attempted to perform an unauthorized operation.
```

Interpretacao tecnica: o pacote local e a conexao ao App Catalog foram validados, mas o aplicativo/ClientId usado pelo PnP.PowerShell ainda nao possui permissao ou consentimento suficiente no tenant para publicar no App Catalog por automacao.

Acao necessaria antes de nova tentativa automatizada:

1. Revisar o consentimento/permissoes delegadas do ClientId usado no PnP.PowerShell.
2. Confirmar que o usuario autenticado continua com permissao administrativa no App Catalog.
3. Reexecutar o script somente apos liberar a permissao necessaria para `Add-PnPApp`.

Enquanto isso nao for resolvido, a alternativa operacional continua sendo a publicacao manual pelo App Catalog.
