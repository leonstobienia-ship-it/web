# V2.9C2 - Correcao do 400 na escrita administrativa

## Erro observado

Durante `AtualizarUsuarioPerfilStatus`, a pre-validacao aprovou a execucao, mas a tentativa manual no tenant retornou:

`SharePoint retornou 400: Bad Request`

O payload exibido misturava campos reais da lista com `DiagnosticoPreValidacao`, que nao existe em `ENAC Usuarios Perfis`.

## Causa provavel

O objeto exibido como payload administrativo continha dados de diagnostico junto dos campos SharePoint. Mesmo quando a camada de escrita monta o body a partir do estado do formulario, a tela nao deve apresentar um payload que contenha campos inexistentes, porque isso torna a aprovacao visual insegura.

## Correcao

- `DiagnosticoPreValidacao` foi removido do `payloadPrevisto`.
- O diagnostico passou a ficar separado em `historicoPrevisto.DiagnosticoPreValidacao`.
- A tela exibe dois campos distintos:
  - `Payload SharePoint`;
  - `Diagnostico`.
- A escrita administrativa usa uma whitelist em `criarPayloadUsuarioPerfilSharePointV29C`.
- Campos `undefined` sao removidos antes do envio.
- O erro SharePoint passa a tentar exibir o corpo retornado, sanitizando e-mails e tokens.
