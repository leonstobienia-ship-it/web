# V2.8E10 - Breakout medido por viewport

## Contexto

A V2.8E9 confirmou que o pacote e o CSS estavam carregando, mas o conjunto menu lateral + painel branco continuava estreito. A medicao feita no navegador indicou largura de `SPPageChrome/body/html` por volta de 659px, enquanto o print ainda mostrava area escura disponivel a direita.

## Diagnostico

- A margem negativa fixa de rodadas anteriores (`calc(50% - 50vw)`) conseguia escapar do canvas, mas cortava a lateral esquerda porque assumia centralizacao que nao existia no WebView.
- A solucao sem margem negativa preservava a lateral esquerda, mas mantinha o componente preso ao container/canvas estreito.
- A V2.8E9 separou o grid interno em `.viewport`, `.enacSistema`, `.sideNav` e `.mainPanel`, mas o wrapper externo do SharePoint continuou limitando a largura inicial.

## Solucao aplicada

A V2.8E10 adiciona breakout medido em runtime no wrapper `.viewport`.

O componente mede:

- a posicao esquerda real do wrapper com `getBoundingClientRect().left`;
- a largura real do viewport com `window.innerWidth` ou `document.documentElement.clientWidth`.

Em seguida, define variaveis CSS no proprio elemento:

- `--enac-breakout-left`;
- `--enac-viewport-width`.

O CSS usa essas variaveis para deslocar apenas o necessario:

- `width: var(--enac-viewport-width)`;
- `max-width: var(--enac-viewport-width)`;
- `margin-left: calc(-1 * var(--enac-breakout-left))`.

Antes de medir, o codigo restaura temporariamente as variaveis para `0px` e `100%`, evitando que uma medicao posterior seja contaminada pelo deslocamento ja aplicado.

## Eventos

A medicao roda:

- na montagem do componente;
- apos `250ms`;
- em `resize`;
- em `orientationchange`.

Todos os listeners, timer e `requestAnimationFrame` sao limpos no unmount.

## Marcadores visuais

O cabecalho agora exibe:

- `UI V2.8E10`;
- `Breakout medido ativo`.

Se `UI V2.8E10` nao aparecer, o pacote novo nao carregou. Se aparecer e a largura continuar presa, sera necessario inspecionar o DOM real da pagina/canvas no navegador.

## Preservacao funcional

Esta alteracao e somente visual/layout. Ela:

- nao acessa dados externos;
- nao toca SharePoint;
- nao altera listas;
- nao altera permissoes;
- nao executa escrita;
- nao inicia Power Automate;
- nao usa APIs administrativas;
- nao altera regras, payloads, fluxos, servicos, modelos ou scripts.

Nao foram usados seletores globais do SharePoint, nem `calc(50% - 50vw)` fixo, `left` negativo fixo ou `transform` negativo.
