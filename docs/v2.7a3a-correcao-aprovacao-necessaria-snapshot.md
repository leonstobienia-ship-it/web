## Causa Tecnica

A pre-validacao lia o campo de aprovacao necessaria por um unico internal name e normalizava o valor apenas como texto simples.

Isso podia classificar incorretamente valores booleanos, choice/object ou variações de internal name como nao aprovados.

## Correcao Aplicada

Foi criada normalizacao defensiva:

`normalizarBooleanoSharePoint(valor): boolean | null`

Valores aceitos como verdadeiro:

- `true`;
- `true`/`True`;
- `SIM`/`Sim`/`sim`;
- `Yes`/`yes`;
- `1`.

Valores aceitos como falso:

- `false`;
- `false`/`False`;
- `NÃO`/`Não`/`não`;
- `Nao`/`nao`;
- `No`/`no`;
- `0`.

Se o valor vier como objeto, a rotina tenta `Label`, `Value`, `Title` e `results`.

Se o valor vier indefinido, nulo ou ilegivel, retorna `null`.
