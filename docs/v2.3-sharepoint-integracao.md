# V2.3 - Integração SharePoint

## Congelamento V2.2

A interface V2.2 homologada deve permanecer preservada. A V2.3 não redesenha telas, campos visuais ou fluxos do protótipo local.

Tag e branch solicitadas:

- `v2.2-interface-homologada`
- `dev/v2.3-sharepoint-integracao`

Observação: neste ambiente local, o comando `git` não está disponível no PATH. A criação efetiva da tag e da branch deve ser feita em uma estação com Git disponível.

## Fonte de dados

- Fonte oficial V2.3: SharePoint via webpart SPFx.
- Protótipo HTML: permanece como demonstração V2.2 homologada.
- Integração concentrada em `src/webparts/enacSistema/services/SharePointEnacRepository.ts`.

## Persistência

- Solicitações são lidas de `ENAC Solicitacoes`.
- Usuário autenticado é resolvido por `ENAC Usuarios Perfis.ContaMicrosoft365`.
- Alçadas são lidas de `ENAC Alcadas`.
- Snapshots são criados em `ENAC Snapshots Regras`.
- Snapshot de compra é vinculado em `ENAC Solicitacoes.SnapshotAprovacaoCompra`.

## Resolução de alçada

1. Considerar apenas regras ativas e vigentes.
2. Filtrar por processo, tipo de solicitação, obra e valor.
3. Regra específica de obra prevalece sobre regra geral.
4. Regra ilimitada não usa valor máximo.
5. Sobreposições e lacunas devem ser detectadas antes do uso operacional.

## Substituição

A alçada não guarda substituto direto nesta rodada. O aprovador base vem da alçada; o aprovador efetivo é resolvido pelo cadastro do usuário:

- `SubstitutoTemporario`
- `InicioSubstituicao`
- `FimSubstituicao`

## Segurança

A V2.3 prepara a arquitetura para Power Automate e permissões reais, mas ainda não representa a segurança definitiva do fluxo. Alterações de usuários, alçadas, histórico e snapshots devem ser restringidas por permissões SharePoint.
