# V3.3A - PostgreSQL Local

## Objetivo

Validar a persistencia local do ERP ENAC em PostgreSQL, sem producao, sem SharePoint, sem Entra e sem automacoes.

## Escopo entregue

- `docker-compose.yml` com PostgreSQL 16 local.
- `.env.example` com variaveis de desenvolvimento.
- Backend com pool PostgreSQL via `pg`.
- Protecao para permitir apenas `enac_erp_dev` em `localhost`, `127.0.0.1` ou `::1`.
- `GET /health` preservado.
- `GET /health/db` criado para validar conexao local.
- Scripts `npm run migrate` e `npm run seed` no backend.
- Endpoints GET somente leitura:
  - `/empresas`
  - `/usuarios`
  - `/clientes`
  - `/fornecedores`
  - `/obras`
  - `/centros-custo`

## Como subir PostgreSQL local

Na raiz do repositorio:

```powershell
Copy-Item .env.example .env
docker compose up -d postgres
docker compose ps
```

O banco local esperado e:

- database: `enac_erp_dev`
- user: `enac_erp_dev`
- host: `127.0.0.1`
- port: `5432`

## Como rodar migration e seed

```powershell
cd server
npm install
npm run migrate
npm run seed
```

A seed cria registros marcados com `DEV_LOCAL_V3_3A`.

## Como rodar a API

```powershell
cd server
npm run build
npm start
```

## Observacao tecnica de host

A primeira tentativa de validacao retornou timeout/503 porque a conexao PostgreSQL nao apontava para o host acessivel pelo backend local.

Para backend rodando diretamente no Windows/host, use:

```text
DATABASE_URL=postgres://enac_erp_dev:enac_erp_dev_password@127.0.0.1:5432/enac_erp_dev
```

ou `localhost:5432`.

Use o hostname `postgres` apenas quando o backend tambem estiver rodando dentro da rede Docker Compose. Backend no host Windows nao deve usar `postgres` como hostname.
