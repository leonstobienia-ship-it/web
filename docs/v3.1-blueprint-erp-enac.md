# V3.1 - Blueprint ERP ENAC

## Decisão de produto

O Sistema ENAC deve evoluir de um fluxo operacional de compras/pagamentos para um ERP verticalizado de engenharia/obras, gestão patrimonial/locação e financeiro operacional.

O sistema atual em React/SPFx/SharePoint continua válido como módulo operacional controlado e como aprendizado de fluxo, permissões, escrita protegida e homologação assistida. O alvo do ERP, porém, não deve usar SharePoint Lists como banco principal para transações críticas.

## Arquitetura-alvo

| Camada | Decisão |
|---|---|
| Fonte de verdade operacional | PostgreSQL |
| Camada de negócio | API própria |
| Frontend | SPA React/TypeScript autenticada via Microsoft Entra ID |
| Documentos | Bibliotecas SharePoint com versionamento e metadados |
| Relatórios | BI em réplica/warehouse |
| Identidade | Entra ID, app roles e grupos |
| Integrações críticas | Sempre pelo backend |

## MVP ERP

| Frente | Escopo mínimo |
|---|---|
| Cadastros mestres | CNPJ, site, prédio, sala/unidade, vaga, parte, centro de custo e conta analítica |
| CRM leve | Lead, oportunidade, proposta/orçamento, aprovação e contrato |
| Contratos | Obra, serviço e locação com partes, escopo, valores, prazos, retenções, reajustes e aditivos |
| Obras e medições | Projeto, WBS, orçamento base, cronograma, diário, evidências, medição e faturamento |
| Financeiro operacional | AR, cobrança, inadimplência, AP, programação, pagamento, baixa e conciliação |
| Locação e ocupação | Contrato, caução, cobrança recorrente, reajuste, renovação, rescisão e vacância |
| Estacionamento simples | Vagas, regras, mensalistas, uso, fechamento, cobrança e repasse |

## Fronteira do MVP

Entram no MVP: Entra ID, usuários e papéis; cadastros; CRM leve; contratos de obra e locação; obras/WBS/medições; AR/AP/cobrança/conciliação; ocupação de salas; estacionamento simples.

Ficam para depois: restaurante como PDV completo, cowork full-service, contabilidade estatutária completa dentro do ERP, automações fiscais muito específicas, portal externo sofisticado, analytics preditivo e mobile app nativo.

## Requisitos não funcionais mínimos

- Multi-CNPJ e multisite com `legal_entity_id` e `site_id` em transações.
- Row-level security no PostgreSQL e filtro obrigatório no backend.
- Auditoria append-only para aprovações, baixas, estornos, alterações contratuais, exportações e administração.
- Outbox, filas, idempotência e retries para webhooks e integrações.
- Backup com WAL archiving, PITR e testes periódicos de restore.
- SharePoint restrito a documentos, metadados, versionamento e colaboração.
- Dashboards em camada analítica, não em consultas pesadas no OLTP.
