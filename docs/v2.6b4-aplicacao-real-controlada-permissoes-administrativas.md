# V2.6B.4 - Aplicacao Real Controlada de Permissoes Administrativas

Data: 2026-06-08

Branch: `dev/v2.3-sharepoint-integracao`

## Objetivo

Preparar a aplicacao real controlada das permissoes finas nas quatro listas administrativas da ENAC, usando os grupos ENAC criados manualmente por Leon.

Codex nao conecta ao SharePoint, nao executa o script, nao usa `-Apply`, nao aplica permissoes, nao altera tenant/listas/dados e nao inicia Power Automate.

## Escopo

Listas afetadas:

- ENAC Usuarios Perfis
- ENAC Alcadas
- ENAC Historico Configuracoes
- ENAC Snapshots Regras

Fora do escopo:

- listas operacionais;
- membros de grupos;
- criacao ou exclusao de grupos;
- itens de listas;
- Power Automate;
- escrita operacional geral.

## Grupos afetados

O grupo `ENAC Campo Engenharia` existe, mas nao recebe permissao nas listas administrativas nesta rodada.

## Riscos

- Quebra de heranca em lista administrativa altera o modelo de acesso imediatamente.
- Se algum grupo estiver ausente, o script deve abortar antes de alterar qualquer lista.
- Se `Owners` nao for mantido com `Full Control`, rollback pode ficar mais dificil.
- Se a aplicacao falhar apos quebrar heranca em uma lista, Leon deve parar e registrar o erro antes de continuar.

## Rollback

Antes de aplicar, Leon deve guardar evidencias do estado atual. A auditoria V2.6B.3B/V2.6B.3D ja registrou que as quatro listas administrativas herdavam permissoes do site.

Rollback esperado em caso de falha:

1. Parar a execucao.
2. Registrar lista afetada e mensagem de erro.
3. Conferir se `Obras em Andamento Owners` manteve `Full Control`.
4. Restaurar heranca manualmente ou por script de rollback futuro, se necessario.
5. Nao iniciar Power Automate.

## Comando ConnectedPreflight

Apos a correcao V2.6B.4A, executar o preflight conectado antes de nova tentativa de `Apply`:

```powershell
pwsh -File ".\scripts\sharepoint\11-permissoes-finas-v2.6b-apply.ps1" `
  -SiteUrl "https://enaccombr.sharepoint.com/sites/Equipe.Obras" `
  -Tenant "enaccombr.onmicrosoft.com" `
  -ClientId "8994fd01-5b9b-4e8b-bc11-41c58aa91043" `
  -AuthMode "DeviceLogin" `
  -Ambiente "V2.6B.4" `
  -ConnectedPreflight
```

Esse modo conecta ao SharePoint, valida site, niveis de permissao, listas administrativas e grupos por nome exato, mas nao quebra heranca e nao aplica permissoes.

## Comando de aplicacao real

Somente Leon deve executar, apenas apos revisar o dry-run:

```powershell
cd "C:\Users\leon\OneDrive - enac.com.br\Documentos\Sistema ENAC"

pwsh -File ".\scripts\sharepoint\11-permissoes-finas-v2.6b-apply.ps1" `
  -SiteUrl "https://enaccombr.sharepoint.com/sites/Equipe.Obras" `
  -Tenant "enaccombr.onmicrosoft.com" `
  -ClientId "8994fd01-5b9b-4e8b-bc11-41c58aa91043" `
  -AuthMode "DeviceLogin" `
  -Ambiente "V2.6B.4" `

  -ConfirmPermissoes "APLICAR-PERMISSOES-V2.6B-ENAC"
```

## Criterios de parada

Parar antes de `-Apply` se:

- algum grupo ENAC nao existir;
- algum grupo tiver nome divergente;
- alguma lista administrativa nao for encontrada;
- dry-run apontar lista operacional no escopo;
- script planejar remover Owners;
- script planejar remover usuarios/membros;
- script planejar excluir grupos;
- houver erro de autenticacao ou permissao inesperado;
- qualquer etapa mencionar Power Automate.
- `ConnectedPreflight` falhar em `Get-PnPGroup` ou qualquer outra validacao.

Parar apos `-Apply` se:

- uma das quatro listas falhar;
- Owners perder `Full Control`;
- listas operacionais forem alteradas;
- houver erro parcial sem rollback claro.
