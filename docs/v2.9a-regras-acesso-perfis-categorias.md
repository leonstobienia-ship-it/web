# V2.9A - Regras De Acesso, Perfis E Categorias

## Regra Principal

O usuario do sistema deve ser identificado pelo login Microsoft 365 e vinculado ao cadastro interno em `ENAC Usuarios Perfis`, preferencialmente pelo campo `ContaMicrosoft365`.

O front-end nao deve permitir elevacao livre de perfil.

## Categorias Funcionais

| Categoria | Uso previsto |
| --- | --- |
| Campo / Engenharia | Criacao e acompanhamento de solicitacoes da obra. |
| Compras / Financeiro | Pedido, nota fiscal e programacao financeira. |
| Planejamento / Aprovacao | Validacao tecnica e aprovacao dentro da alcada. |
| Diretoria | Aprovacao superior, visao geral e excecoes. |
| Administrador do Sistema | Usuarios, perfis, alcadas, auditoria e parametros. |
| Consulta / Leitura | Visualizacao sem escrita. |

## Menus Administrativos

Os menus abaixo ficam visiveis somente quando o perfil ativo e autorizado for `AdministradorSistema`:

- `Usuários`;
- `Alçadas`;
- `Auditoria`.

Ocultar botoes no front-end melhora a experiencia, mas nao substitui seguranca final. Qualquer escrita futura tambem devera validar permissao antes de executar.

## Usuario Nao Cadastrado Ou Inativo

Quando a webpart estiver consumindo SharePoint readonly:

- usuario nao cadastrado deve ver alerta `Usuário não cadastrado no Sistema ENAC`;
- usuario inativo deve ver alerta de bloqueio;
- perfil nao autorizado deve ser bloqueado;
- acoes operacionais e administrativas devem permanecer bloqueadas ate regularizacao.

## Administrador

Administrador pode ter modo controlado de visualizacao/teste de perfis apenas quando esse perfil estiver atribuido ao proprio usuario. Esse comportamento deve continuar documentado durante a homologacao.
