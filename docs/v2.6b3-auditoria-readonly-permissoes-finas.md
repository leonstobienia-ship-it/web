## Comando manual para Leon

```powershell
cd "C:\Users\leon\OneDrive - enac.com.br\Documentos\Sistema ENAC"

pwsh -File ".\scripts\sharepoint\12-permissoes-finas-v2.6b-readonly-auditoria.ps1" `
  -SiteUrl "https://enaccombr.sharepoint.com/sites/Equipe.Obras" `
  -Tenant "enaccombr.onmicrosoft.com" `
  -ClientId "<CLIENT-ID-PROVISIONAMENTO-OU-READONLY>" `
  -AuthMode "DeviceLogin"
```

Como a auditoria e somente leitura, pode ser usado o ClientId readonly se ele tiver permissao suficiente para ler grupos/listas/permissoes. Se usar o app de provisionamento, ainda assim o script nao contem comandos de escrita.

## Dados lidos

- Titulo e URL do site.
- Definicoes de permissoes disponiveis no site.
- Grupos SharePoint planejados para a ENAC.
- Contagem de membros dos grupos, sem exportar e-mails.
- Outros grupos SharePoint com `ENAC` no nome.
- Existencia das listas administrativas.
- ItemCount das listas administrativas.
- Indicador de heranca unica das listas administrativas, quando disponivel.
- Principais e papeis atualmente vinculados as listas administrativas, quando a API permitir leitura.
- Comparacao basica com o plano V2.6B.

## Dados nao exportados

- Tokens, codigos de autenticacao ou segredos.
- E-mails de membros.
- Conteudo de itens das listas.
- Dados V2.3B-TESTE ou V2.6A-TESTE.
- Documentos, anexos ou dados operacionais.

## Criterios para versionar o relatorio

O relatorio gerado em `sharepoint/auditoria-permissoes-finas-v2.6b3.md` podera ser versionado somente se:

- nao contiver e-mails reais;
- nao contiver tokens, codigos, segredos ou URLs temporarias de autenticacao;
- nao contiver nomes de fornecedores, descricoes operacionais, anexos ou dados de itens;
- limitar-se a grupos, listas, heranca e papeis;
- for revisado por Leon antes do commit.

## V2.6B.3A - Correcao de tolerancia a permissao de grupos

Leon executou a auditoria readonly com o ClientId readonly `0dab19b3-8e48-4f89-ad94-1446b08d3781` e depois com o ClientId de provisionamento `8994fd01-5b9b-4e8b-bc11-41c58aa91043`. Nos dois casos a conexao ocorreu, mas a leitura de grupos falhou em `Get-PnPGroup` com `Access is denied. 0x80070005`.

A causa provavel e falta de permissao do app/usuario para enumerar grupos SharePoint. Isso nao indica escrita nem alteracao no tenant.

O script foi corrigido para:

- registrar `Auditoria de grupos: LIMITADA`;
- informar o motivo sanitizado da falha;
- marcar grupos planejados como `NAO_CONFIRMADO`;
- continuar auditando as quatro listas administrativas;
- tentar ler permissoes de listas em blocos protegidos;
- gerar relatorio parcial mesmo quando grupos nao puderem ser enumerados.

Se grupos continuarem sem permissao, o relatorio parcial ainda e valido para confirmar listas administrativas, heranca e eventuais limitacoes de leitura.
