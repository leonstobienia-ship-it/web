# V3.4C - Pedido de Compra MVP ERP ENAC

## Objetivo

A V3.4C implementa o Pedido de Compra MVP gerado a partir de uma cotacao formal com fornecedor vencedor escolhido. A etapa fecha o ciclo inicial de compras ate pedido confirmado, sem recebimento fisico, sem nota fiscal, sem contas a pagar e sem movimentacao financeira.

Esta etapa usa somente PostgreSQL local `enac_erp_dev`.

## Duplicidade

A migration cria indice unico parcial:

```sql
idx_pedidos_compra_cotacao_ativo
```

Regra: uma cotacao nao pode gerar mais de um pedido ativo. Pedidos `CANCELADO` ficam fora do indice para permitir evolucao futura controlada.

## Status

Status previstos:

- `RASCUNHO`
- `EMITIDO`
- `ENVIADO_FORNECEDOR`
- `CONFIRMADO`
- `PARCIALMENTE_RECEBIDO`
- `RECEBIDO`
- `CANCELADO`

Transicoes implementadas na V3.4C:

- `RASCUNHO -> EMITIDO`
- `EMITIDO -> ENVIADO_FORNECEDOR`
- `ENVIADO_FORNECEDOR -> CONFIRMADO`
- `RASCUNHO -> CANCELADO`
- `EMITIDO -> CANCELADO`
- `ENVIADO_FORNECEDOR -> CANCELADO`

`PARCIALMENTE_RECEBIDO` e `RECEBIDO` existem como status controlados, mas nao sao usados operacionalmente nesta etapa.

## Regras de geracao

- Cotacao deve existir.
- Cotacao deve estar em `FORNECEDOR_ESCOLHIDO`.
- Cotacao `CANCELADA` nao gera pedido.
- Fornecedor vencedor deve existir.
- Itens do pedido sao herdados da resposta do fornecedor vencedor.
- Obra e centro de custo sao herdados da solicitacao.
- Valor total do pedido e calculado pela soma dos itens.
- Pedido ativo duplicado para a mesma cotacao retorna `409`.
- Nao cria nota fiscal.
- Nao cria contas a pagar.
- Nao cria movimentacao financeira.

## Smoke test

Script:

```powershell
cd server
npm.cmd run smoke:pedidos
```

O smoke:

- valida `/health`;
- valida `/health/db`;
- cria solicitacao `DEV_LOCAL_V3_4C`;
- cria cotacao formal com fornecedor vencedor;
- gera pedido a partir da cotacao;
- valida listagem e detalhe;
- executa `RASCUNHO -> EMITIDO -> ENVIADO_FORNECEDOR -> CONFIRMADO`;
- valida duplicidade com HTTP `409`.

- Nenhuma nota fiscal.
- Nenhum financeiro ou contas a pagar.
- Nenhuma programacao bancaria.
- Nenhum pagamento.
- Nenhuma escrita real no SharePoint.
- Nenhuma alteracao Entra.
- Nenhuma automacao.
- Nenhum banco de producao.
- Nenhum `.env` commitado.
