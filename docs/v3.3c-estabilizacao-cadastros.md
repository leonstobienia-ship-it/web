# V3.3C - Estabilizacao dos Cadastros Mestres

## Objetivo

Estabilizar os cadastros mestres e o ambiente local antes de iniciar Solicitacao de Compra.

A etapa permanece restrita ao ambiente local. Nao ha escrita real no SharePoint, alteracao Entra, automacoes, banco de producao, modulo de compras ou `DELETE` fisico.

## Ambiente local

O backend agora carrega `.env` de desenvolvimento por caminho absoluto, independentemente de ser iniciado a partir da raiz do projeto ou do diretorio `server`.

Ordem aplicada:

1. Variaveis ja presentes em `process.env` vencem sempre.
2. Em desenvolvimento, o backend tenta carregar `.env` da raiz do projeto.
3. Em desenvolvimento, o backend tenta carregar `server/.env`.
4. Arquivos `.env` nao sobrescrevem variaveis ja definidas.
5. Se `DATABASE_URL` ja existia antes do `.env`, ela vence.
6. Se nao havia `DATABASE_URL` explicita, o backend monta a conexao pelos campos `POSTGRES_*`.
7. Em `NODE_ENV=production`, o backend nao carrega `.env` automaticamente.

O `.env` real continua local e ignorado pelo Git.

## DATABASE_URL por cenario

Backend rodando no Windows/host:

```text
DATABASE_URL=postgres://enac_erp_dev:enac_erp_dev_password@127.0.0.1:5432/enac_erp_dev
```

Backend rodando dentro da rede Docker Compose:

```text
DATABASE_URL=postgres://enac_erp_dev:enac_erp_dev_password@postgres:5432/enac_erp_dev
```

O host `postgres` deve ser usado somente quando a API tambem estiver em container na mesma rede Compose. Para `npm start` no Windows/host, use `127.0.0.1` ou `localhost`.

## Troubleshooting PostgreSQL local

Sintoma: `GET /health/db` retorna `503`.

Causas comuns:

- `DATABASE_URL` apontando para `postgres:5432` enquanto o backend roda no Windows/host.
- `.env` local com senha diferente da senha usada na criacao do container/volume PostgreSQL.
- `DATABASE_URL` dentro do `.env` desalinhada dos campos `POSTGRES_*`; sem `DATABASE_URL` explicita na sessao, a V3.3C usa `POSTGRES_*`.
- Container ainda nao esta `healthy`.
- Porta `5432` ocupada ou nao publicada no host.
- API iniciada antes do PostgreSQL ficar pronto.

Checagens:

```powershell
docker compose ps
Get-Content .env | Select-String DATABASE_URL
cd server
npm.cmd start
```

Se o container ja foi criado com outra senha, ajuste o `.env` local para a senha real do container ou recrie o volume local de desenvolvimento. Nao commitar `.env`.

## Backend

Validações confirmadas ou ajustadas:

- Campos obrigatorios.
- UUID em IDs e FKs recebidas.
- `tipo_pessoa` controlado.
- `status` controlado.
- `uf` validada por lista de UFs brasileiras.
- Datas em `YYYY-MM-DD`.
- `valor_previsto` numerico.
- `email` com validacao simples quando informado.
- `404` para ID inexistente.
- `400` para payload invalido.
- `409` para violacao de chave unica.
- Erros padronizados em JSON.

## Banco de dados

Nao foi criada migration `003_constraints_cadastros.sql`, porque as restricoes relevantes ja existem:

- `idx_clientes_company_cpf_cnpj`: unico parcial em `clientes(company_id, cpf_cnpj)` quando `cpf_cnpj` nao e nulo.
- `idx_fornecedores_company_cpf_cnpj`: unico parcial em `fornecedores(company_id, cpf_cnpj)` quando `cpf_cnpj` nao e nulo.
- `centros_custo`: constraint unica `UNIQUE (company_id, codigo)`.
- `obras`: constraint unica `UNIQUE (company_id, codigo)`.

A V3.3C preserva as migrations anteriores.

## Frontend

Melhorias de estabilizacao:

- Mensagens de erro vindas da API exibem `code` e detalhes quando disponiveis.
- Botao `Salvar` fica desabilitado durante salvamento.
- Botao `Novo`, `Editar`, `Inativar` e `Reativar` respeitam estado de salvamento/carregamento.
- Inativacao pede confirmacao.
- Campos obrigatorios mostram selo visual.
- Status ativo/inativo passou a usar chip visual.
- Formulario e selecao sao limpos apos criacao.

## Smoke test

Script:

```powershell
cd server
npm.cmd run smoke:cadastros
```

Pre-condicao: a API deve estar rodando em `http://127.0.0.1:3333`, salvo se `ENAC_ERP_API_BASE_URL` apontar para outro backend local.

O smoke test valida:

- `GET /health`
- `GET /health/db`
- `GET /clientes`
- `GET /fornecedores`
- `GET /obras`
- `GET /centros-custo`
