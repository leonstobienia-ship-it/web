# V2.7A.2A - Pre-validacao Especifica Do Item

Data: 2026-06-08

Branch: `dev/v2.3-sharepoint-integracao`

## Diagnostico

Leon criou manualmente o item de teste provavel `ID 11` na Lista 02 e configurou as flags V2.7A no Property Pane.

O painel exibido em `adminHistorico` confirmava apenas a validacao generica de flags, perfil e acoes permitidas. Ele ainda nao confirmava:

- ID do item de teste;
- leitura do item na Lista 02;
- marcador `V2.7A-TESTE` no item;
- status atual;
- status destino;
- transicao pretendida;
- campos obrigatorios;
- lista/campo que seriam alterados;
- valor anterior e valor novo previstos;
- historico previsto para o item.

Por esse motivo, a escrita manual V2.7A ficou bloqueada.

## Correcao

A webpart passa a exigir uma pre-validacao especifica do item antes de exibir o botao de escrita operacional.

Foram adicionadas propriedades seguras ao Property Pane:

| Propriedade | Padrao |
| --- | --- |
| `itemTesteOperacionalIdV27A` | vazio |
| `acaoTesteOperacionalV27A` | `AtualizarStatusRequisicao` |
| `statusDestinoTesteOperacionalV27A` | `Aguardando aprovação` |
| `valorTesteOperacionalV27A` | vazio |
| `observacaoTesteOperacionalV27A` | `V2.7A-TESTE - teste operacional restrito` |

As flags existentes permanecem preservadas:

| Propriedade | Regra |
| --- | --- |
| `habilitarEscritaOperacionalV27A` | desligada por padrao |
| `modoTesteOperacionalV27A` | desligada por padrao |
| `permitirSomenteItensTesteV27A` | ligada por padrao |
| `marcadorTesteOperacionalV27A` | sempre `V2.7A-TESTE` |
| `exigirConfirmacaoManualV27A` | ligada por padrao |
| `confirmacaoManualV27A` | deve ser `CONFIRMAR-ESCRITA-OPERACIONAL-V2.7A-ENAC` somente na pagina restrita de teste |

## Pre-validacao Readonly

Foi criado o metodo `preValidarEscritaOperacionalRestritaV27A()`.

Durante a pre-validacao ele usa apenas `GET` e retorna:

- flags validas;
- usuario atual reconhecido;
- perfil atual;
- acao pretendida;
- item de teste;
- item encontrado;
- marcador encontrado;
- status atual;
- status destino;
- transicao permitida;
- campos obrigatorios presentes;
- snapshot existente, quando aplicavel;
- historico previsto;
- lista que sera alterada;
- campo que sera alterado;
- valor anterior previsto;
- valor novo previsto;
- `podeExecutar`;
- motivos de bloqueio.

## Regras De Bloqueio

A escrita continua bloqueada se:

- `itemTesteOperacionalIdV27A` estiver vazio ou zero;
- o item nao for encontrado;
- o marcador `V2.7A-TESTE` nao aparecer no titulo ou descricao;
- o status atual nao permitir a transicao;
- a acao nao estiver permitida para o perfil;
- as flags nao estiverem coerentes;
- a confirmacao manual configurada nao for exatamente a esperada;
- campos obrigatorios minimos estiverem ausentes.

Para a acao `AtualizarStatusRequisicao`, a transicao inicial controlada aceita `Aberta` ou `Recebida` para `Aguardando aprovação`.

## Interface

O painel `adminHistorico` passa a exibir:

- item configurado;
- acao pretendida;
- status destino;
- item lido;
- marcador confirmado;
- status atual e destino;
- transicao;
- campos obrigatorios;
- lista/campo;
- valor previsto;
- historico previsto;
- alertas;
- `pode executar`.

O botao de escrita so aparece se:

- a pre-validacao especifica foi executada;
- `podeExecutar = true`;
- o item validado e igual ao `itemTesteOperacionalIdV27A`;
- o marcador `V2.7A-TESTE` foi confirmado;
- a confirmacao final digitada bate exatamente com `confirmacaoManualV27A`.

## Orientacao Para O Item 11

Na pagina restrita de teste, Leon deve configurar:

| Propriedade | Valor |
| --- | --- |
| `itemTesteOperacionalIdV27A` | `11` |
| `acaoTesteOperacionalV27A` | `AtualizarStatusRequisicao` |
| `statusDestinoTesteOperacionalV27A` | `Aguardando aprovação` |
| `observacaoTesteOperacionalV27A` | `V2.7A-TESTE - teste operacional restrito` |
| `confirmacaoManualV27A` | `CONFIRMAR-ESCRITA-OPERACIONAL-V2.7A-ENAC` |

Se a pre-validacao nao confirmar item `11`, marcador, status atual e transicao, parar.
