# V2.9C1 - Correcao de pre-validacao de usuario existente

## Erro observado

Ao editar um usuario existente, a pre-validacao podia indicar `CONTA_M365_DUPLICADA` mesmo quando a conta Microsoft 365 encontrada pertencia ao proprio item em edicao.

## Causa

A validacao de duplicidade precisava diferenciar dois cenarios:

- criacao de novo usuario, onde qualquer conta/e-mail/ID ja existente deve bloquear;
- edicao de usuario existente, onde a conta/e-mail/ID do proprio item alvo nao deve ser tratada como duplicidade real.

## Regra corrigida

Para `CriarUsuarioSistema`:

- `ContaMicrosoft365Id` existente bloqueia;
- `EmailCorporativo` existente bloqueia;
- `UsuarioInternoId` existente bloqueia.

Para `AtualizarUsuarioPerfilStatus`:

- se a duplicidade pertence a outro item, bloqueia;
- se a duplicidade pertence ao proprio item alvo, nao bloqueia;
- a tela registra diagnostico `DUPLICIDADE_PROPRIO_ITEM_IGNORADA`, sem bloquear.

## Saida da pre-validacao

A tela de usuarios passa a exibir:

- status das travas;
- usuario atual e permissao administrativa;
- item alvo;
- conta/e-mail sanitizados;
- duplicidade real por conta, e-mail e ID interno;
- duplicidade do proprio item ignorada;
- pode executar.

## Flags de teste manual

Para repetir o teste, Leon deve configurar no Property Pane:

- `habilitarEscritaAdministrativaV29C = true`;
- `modoTesteAdministrativoV29C = true`;
- `exigirConfirmacaoAdministrativaV29C = true`;
- `confirmacaoAdministrativaV29C = CONFIRMAR-ESCRITA-ADMINISTRATIVA-V2.9C-ENAC`.

A escrita real continua dependente de validacao manual e confirmacao final na tela.
