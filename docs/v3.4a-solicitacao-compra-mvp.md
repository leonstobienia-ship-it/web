# V3.4A - Solicitação de Compra MVP ERP ENAC

## Objetivo

A V3.4A implementa o primeiro módulo operacional de compras no ERP ENAC local: Solicitação de Compra com cabeçalho, itens, persistência PostgreSQL, API Node.js e tela React.

Esta etapa usa somente o banco local `enac_erp_dev`. Não há SharePoint, Entra, automações, banco de produção, `DELETE` físico, cotação, pedido de compra, nota fiscal, financeiro ou aprovação por alçada.

## Status e transições

Status controlados:

- `RASCUNHO`
- `ENVIADA`
- `EM_ANALISE`
- `APROVADA_PARA_COTACAO`
- `DEVOLVIDA`
- `CANCELADA`

Transições liberadas na V3.4A:

- `RASCUNHO -> ENVIADA`
- `ENVIADA -> EM_ANALISE`
- `EM_ANALISE -> DEVOLVIDA`
- `DEVOLVIDA -> RASCUNHO`
- `RASCUNHO -> CANCELADA`
- `ENVIADA -> CANCELADA`
- `EM_ANALISE -> CANCELADA`

`APROVADA_PARA_COTACAO` existe no enum para compatibilidade futura, mas não há ação operacional para atingir esse status nesta etapa.

## Validações

A API valida:

- UUID em `company_id`, `obra_id`, `centro_custo_id`, `solicitante_id` e `id`.
- Campos obrigatórios do cabeçalho.
- Prioridade controlada.
- Data no formato `YYYY-MM-DD`.
- Pelo menos 1 item.
- Quantidade maior que zero.
- Valor unitário maior ou igual a zero.
- Obra, centro de custo e solicitante pertencentes à empresa.
- Bloqueio de edição para `CANCELADA` e `APROVADA_PARA_COTACAO`.
- Bloqueio de transição ilegal de status.

Erros:

- `400` para payload inválido.
- `404` para ID inexistente.
- `409` para conflito de status/transição.
- `503` apenas para falha de banco.

As queries usam parâmetros do `pg`; não há concatenação de SQL com entrada de usuário.
