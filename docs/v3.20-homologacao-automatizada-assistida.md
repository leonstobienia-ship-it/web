# V3.20 - Homologacao Automatizada Assistida Ponta a Ponta

## Objetivo

A V3.20 cria uma camada de homologacao automatizada e assistida para validar o fluxo operacional completo do ERP ENAC em ambiente local.

A etapa nao altera regras de negocio, nao cria migration, nao cria endpoint novo e nao ativa integracoes externas reais.

## Script

Script criado:

```powershell
cd "C:\Users\leon\OneDrive - enac.com.br\Documentos\Sistema ENAC\server"
npm.cmd run homologacao:e2e
```

Arquivo:

```text
server/src/scripts/homologacaoE2E.ts
```

Marcador da execucao:

```text
DEV_LOCAL_E2E_V3_20
```

Massa base reutilizada:

```text
DEV_LOCAL_HOMOLOGACAO_ENAC_V316
```

## Fluxo Validado

O E2E valida:

1. health da API e banco local;
2. seed de homologacao consolidada;
3. cliente, fornecedor, obra, centro de custo, usuarios e perfis;
4. contrato ativo e aditivo aprovado;
5. orcamento base aprovado e resumo gerencial;
6. planejamento executivo ativo;
7. solicitacao, cotacao, mapa comparativo e pedido confirmado;
8. nota fiscal de entrada vinculada ao pedido;
9. conta a pagar vinculada a NF;
10. programacao de pagamento, liberacao e conferencia;
11. baixa manual controlada local ja existente na massa de homologacao;
12. medicao e pedido de faturamento manual;
13. previsto x realizado e curva mensal;
14. dashboard executivo;
15. central de tarefas;
16. riscos e pendencias;
17. documento mock/local vinculado a NF;
18. auditoria;
19. rotas proibidas e ausencia de operacoes reais.

## Idempotencia

O script pode ser executado mais de uma vez.

- A seed V3.16/V3.17 ja e idempotente.
- A tarefa V3.20 usa codigo fixo `E2E-V3-20-TAREFA-001`.
- A pendencia V3.20 usa codigo fixo `E2E-V3-20-RISCO-001`.
- O documento V3.20 usa referencia local `mock://homologacao/v3.20/e2e-nota-fiscal`.
- Nenhuma conta a pagar, programacao ou baixa nova e criada pelas evidencias V3.20.

## Relatorios

O script gera:

```text
reports/homologacao/v3.20/homologacao-e2e-<timestamp>.md
reports/homologacao/v3.20/homologacao-e2e-<timestamp>.json
```

Para preservar `git status` limpo em revalidacoes pos-commit, se ja existir um par de relatorios V3.20, o script preserva os arquivos existentes. Para forcar nova evidencia:

```powershell
$env:ENAC_E2E_FORCE_REPORT="1"
npm.cmd run homologacao:e2e
Remove-Item Env:\ENAC_E2E_FORCE_REPORT
```

## Playwright

Nao havia Playwright, Cypress ou workflow E2E UI configurado no projeto no inicio da V3.20.

A V3.20 nao adiciona dependencia nova. A validacao visual assistida deve usar o Browser interno do Codex conforme roteiro em `docs/erp/homologacao-automatizada-assistida.md`.

## Restricoes Mantidas

- Sem pagamento real.
- Sem baixa nova real.
- Sem CNAB.
- Sem integracao bancaria.
- Sem banco de producao.
- Sem NFS-e real.
- Sem prefeitura.
- Sem boleto real.
- Sem cobranca real.
- Sem SharePoint real.
- Sem Microsoft Graph real.
- Sem Entra real.
- Sem Power Automate real.
- Sem upload externo real.
- Sem `DELETE` fisico.

Avisos conhecidos nao bloqueantes:

- Vite pode alertar sobre chunk acima de 500 kB.
- Git no Windows pode alertar sobre LF/CRLF.
