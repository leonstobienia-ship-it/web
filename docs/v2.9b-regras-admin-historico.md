# V2.9B - Regras Administrativas E Historico

## Administrador X Diretoria

Diretoria nao e automaticamente Administrador do Sistema.

Para administrar, o usuario deve estar ativo e com perfil ativo `AdministradorSistema`. `PodeAdministrarConfiguracoes` continua como permissao relevante, mas a UI V2.9B exige perfil ativo de administrador para exibir o painel.

## Pre-Validacao

Todas as acoes administrativas exigem:

- usuario atual ativo;
- perfil ativo `AdministradorSistema`;
- flags V2.9B ligadas;
- modo teste administrativo ativo;
- token exato;
- marcador `V2.9B-ADMIN-TESTE`;
- payload minimo valido;
- historico previsto.

## Validacoes De Usuario

- email valido;
- `ContaMicrosoft365Id` presente para criacao;
- `UsuarioInternoId` unico;
- `EmailCorporativo` unico;
- choice real de `PerfilPrincipal`;
- booleans de permissao previstos.

## Validacoes De Alcada

- `ValorMinimo >= 0`;
- se nao ilimitado, `ValorMaximo >= ValorMinimo`;
- se ilimitado, `ValorMaximo` deve ser ignorado;
- aprovador principal deve existir e estar ativo;
- regra potencialmente sobreposta deve bloquear para revisao manual;
- historico obrigatorio.

## Historico

Cada acao deve registrar futuramente em `ENAC Historico Configuracoes`:

- acao;
- usuario executor;
- item criado/alterado;
- valores antes/depois;
- justificativa;
- data/hora;
- marcador `V2.9B-ADMIN-TESTE` em homologacao.

Na V2.9B, o historico e apenas previsto no painel. Nenhum item de historico e criado.
