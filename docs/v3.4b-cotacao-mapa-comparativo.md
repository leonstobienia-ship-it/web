# V3.4B - Cotacao e Mapa Comparativo ERP ENAC

## Objetivo

A V3.4B implementa o fluxo local de Cotacao e Mapa Comparativo vinculado a Solicitacao de Compra. A cotacao passa a ser um processo agregado: nasce a partir de uma solicitacao, recebe fornecedores participantes, registra respostas por fornecedor, gera mapa comparativo e permite escolher o fornecedor vencedor com justificativa.

Esta etapa usa somente PostgreSQL local `enac_erp_dev`. Nao ha pedido de compra, nota fiscal, financeiro, aprovacao por alcada, SharePoint, Entra, automacoes, banco de producao ou `DELETE` fisico.

## Banco de dados

Migrations envolvidas:

- `database/migrations/005_cotacoes_mapa_comparativo.sql`
- `database/migrations/006_cotacoes_fluxo_formal_v34b.sql`

A migration 005 ja havia sido aplicada e validada. Para preservar historico e evitar reescrever migration antiga, a 006 complementa a estrutura formal pedida para a V3.4B.

Estruturas usadas no modelo formal:

- `cotacoes`: cabecalho do processo de cotacao.
- `cotacoes_fornecedores`: fornecedores convidados e suas respostas consolidadas.
- `cotacoes_itens`: valores por item, fornecedor e solicitacao.
- `mapa_comparativo_cotacao`: resultado do mapa, criterio, justificativa e vencedor.

Campos principais:

- `cotacoes`: `company_id`, `solicitacao_compra_id`, `codigo`, `titulo`, `prazo_resposta`, `status`, `observacoes`, timestamps.
- `cotacoes_fornecedores`: `cotacao_id`, `fornecedor_id`, `status`, `valor_total`, `prazo_entrega_dias`, `condicao_pagamento`, `observacoes`.
- `cotacoes_itens`: `cotacao_fornecedor_id`, `solicitacao_item_id`, `descricao`, `unidade`, `quantidade`, `valor_unitario`, `valor_total`, `marca_modelo`, `prazo_entrega_dias`, `observacoes`.
- `mapa_comparativo_cotacao`: `cotacao_id`, `fornecedor_vencedor_id`, `criterio_decisao`, `justificativa`, `valor_vencedor`, `status`.

## Status

Status de cotacao:

- `RASCUNHO`
- `ENVIADA_FORNECEDORES`
- `RESPOSTAS_RECEBIDAS`
- `MAPA_GERADO`
- `FORNECEDOR_ESCOLHIDO`
- `CANCELADA`

Transicoes implementadas:

- `RASCUNHO -> ENVIADA_FORNECEDORES`
- `ENVIADA_FORNECEDORES -> RESPOSTAS_RECEBIDAS`
- `RESPOSTAS_RECEBIDAS -> MAPA_GERADO`
- `MAPA_GERADO -> FORNECEDOR_ESCOLHIDO`
- `RASCUNHO | ENVIADA_FORNECEDORES | RESPOSTAS_RECEBIDAS | MAPA_GERADO -> CANCELADA`

## API

Endpoints:

```text
GET    /cotacoes
GET    /cotacoes/:id
POST   /cotacoes
PATCH  /cotacoes/:id
PATCH  /cotacoes/:id/enviar-fornecedores
PATCH  /cotacoes/:id/registrar-respostas
PATCH  /cotacoes/:id/gerar-mapa
PATCH  /cotacoes/:id/escolher-fornecedor
PATCH  /cotacoes/:id/cancelar
GET    /cotacoes/mapa-comparativo?cotacao_id=<uuid>
GET    /cotacoes/mapa-comparativo?solicitacao_id=<uuid>
```

Validações:

- `company_id` obrigatorio.
- `solicitacao_id` ou `solicitacao_compra_id` obrigatorio.
- Solicitacao deve existir, pertencer a empresa e nao estar `CANCELADA`.
- Cotacao deve ter pelo menos 1 fornecedor.
- Fornecedor deve existir, estar ativo e pertencer a empresa.
- Respostas devem preservar todos os itens ativos da solicitacao.
- `quantidade > 0` vem da solicitacao.
- `valor_unitario >= 0`.
- `valor_total` por item e por fornecedor calculado pela API.
- Transicao ilegal retorna `409`.
- ID inexistente retorna `404`.
- Payload invalido retorna `400`.
- Falha real de banco retorna `503`.

## Frontend

A aba `Cotações` permite:

- selecionar solicitacao;
- listar cotacoes da solicitacao;
- criar cotacao com fornecedores participantes;
- enviar cotacao aos fornecedores;
- registrar respostas por fornecedor e item;
- gerar mapa comparativo;
- visualizar menor valor por item e menor total;
- escolher fornecedor vencedor com justificativa;
- cancelar cotacao em status permitido.

O frontend consome apenas a API local e nao usa SharePoint.

## Smoke test

Com backend e PostgreSQL locais rodando:

```powershell
cd server
npm.cmd run smoke:cotacoes
```

O smoke:

- valida `/health`;
- valida `/health/db`;
- cria solicitacao `DEV_LOCAL_V3_4B`;
- move para `EM_ANALISE`;
- cria uma cotacao formal com dois fornecedores;
- envia aos fornecedores;
- registra respostas;
- gera mapa comparativo;
- escolhe fornecedor vencedor;
- valida `GET /cotacoes`, `GET /cotacoes/:id` e `GET /cotacoes/mapa-comparativo`.

## Validacao local

Validado em PostgreSQL local `enac_erp_dev` com marcador:

```text
DEV_LOCAL_V3_4B
```

Durante a correcao, o primeiro smoke formal revelou que `cotacoes.data_recebimento` continuava `NOT NULL` por heranca da migration 005. A API passou a preencher `data_recebimento` com `current_date` no fluxo formal, preservando a migration aplicada.
