# V3.10 - Dashboard Executivo da Diretoria

## Objetivo

A V3.10 cria uma camada executiva de leitura para consolidar indicadores de obras, margem, financeiro, faturamento e operação. A etapa parte da V3.9 e reutiliza as visões de previsto x realizado, contratos, orçamento aprovado, medições, faturamento manual, contas a pagar, programações já existentes e baixas manuais já registradas.

A V3.10 não cria operação financeira nova. Não executa pagamento, não cria baixa, não gera CNAB, não integra banco, não emite NFS-e real, não integra prefeitura, não gera boleto, não cria cobrança real, não usa SharePoint real, não usa Entra real e não usa Power Automate.

## Backend

Módulo criado:

```text
server/src/modules/dashboardExecutivo/dashboardExecutivo.routes.ts
```

Endpoints somente leitura:

```http
GET /dashboard-executivo/resumo
GET /dashboard-executivo/obras
GET /dashboard-executivo/alertas
GET /dashboard-executivo/tendencia-mensal
GET /dashboard-executivo/ranking-obras
GET /dashboard-executivo/financeiro
GET /dashboard-executivo/faturamento
GET /dashboard-executivo/operacional
```

Não foram criados endpoints de pagamento, baixa, integração bancária, CNAB, boleto, prefeitura ou emissão fiscal real.

## Fontes de dados

- `obras`, `clientes`, `centros_custo`;
- `contratos_obra` e `contratos_obra_aditivos`;
- `orcamentos_obra` e `orcamentos_obra_cronograma`;
- `pedidos_compra`;
- `notas_fiscais_entrada`;
- `contas_pagar`;
- `contas_pagar_baixas`, somente como histórico local já existente;
- `programacoes_pagamento`;
- `medicoes_obra`;
- `pedidos_faturamento`;
- status agregados de solicitações, cotações, pedidos e notas.

## Indicadores

- Obras totais e ativas.
- Contratos ativos, encerrados e suspensos.
- Valor contratado, valor aditado e valor total contratado.
- Orçamento previsto aprovado.
- Custo comprometido.
- Custo realizado.
- Receita medida.
- Receita faturada manualmente.
- Margem prevista.
- Margem realizada.
- Contas a pagar abertas, vencidas e a vencer.
- Programações liberadas, conferidas e pendentes.
- Medições pendentes.
- Pedidos de faturamento pendentes.
- Saldo a faturar, saldo orçamentário e saldo contratual.

## Fórmulas

```text
valor_total_contratado = valor_contratado + valor_aditado
margem_prevista = valor_total_contratado - orcamento_previsto
margem_realizada = (receita_faturada_manual quando existir, senao receita_medida) - custo_realizado
desvio_orcamento = custo_realizado - orcamento_previsto
saldo_a_faturar = valor_total_contratado - receita_faturada_manual
saldo_orcamentario = orcamento_previsto - custo_realizado
saldo_contratual = valor_total_contratado - receita_medida
```

Custo comprometido usa o maior valor entre pedidos confirmados e contas não canceladas para evitar dupla contagem. Custo realizado usa o maior valor entre contas realizadas e notas aprovadas/provisionadas pelo mesmo motivo.

## Alertas executivos

A API retorna alertas por obra para:

- obra sem orçamento aprovado;
- obra sem contrato ativo;
- custo realizado acima do orçamento previsto;
- margem realizada negativa;
- contas vencidas;
- programação liberada ainda não conferida;
- medição aprovada sem pedido de faturamento;
- pedido de faturamento aprovado ainda não faturado manualmente;
- saldo contratual baixo;
- orçamento aprovado sem cronograma ativo;
- planejamento executivo atrasado.

## Frontend

Tela criada:

```text
web/src/features/dashboardExecutivo/DashboardExecutivoPage.tsx
```

A tela inclui:

- filtros por obra, cliente, centro de custo, contrato, status de obra e período;
- cards executivos de contratado, orçamento, custo, receita, margem, contas, programações e medições;
- resumo de alertas consolidados;
- curva mensal com previsto, faturado, custo e margem;
- ranking de obras;
- tabelas de obras, financeiro, faturamento e operacional.

Os únicos comandos da tela são atualização e limpeza de filtros. Não há botão operacional de pagamento, baixa, banco, CNAB, boleto, prefeitura ou emissão fiscal real.

## Smoke

Script criado:

```text
server/src/scripts/smokeDashboardExecutivo.ts
```

Comando:

```powershell
cd server
npm.cmd run smoke:dashboard-executivo
```

O smoke cria cenário local com marcador `DEV_LOCAL_V3_10`, consulta todos os endpoints da V3.10, valida totais coerentes, confirma que rotas proibidas não existem ou não aceitam operação e confirma que não houve baixa ou programação nova criada pelo dashboard.

## Migration

Não foi criada migration V3.10. As consultas usam estruturas já existentes das versões V3.5 a V3.9.

## Limites da etapa

- A V3.10 é dashboard gerencial, não workflow operacional.
- Não altera regras de contratos, orçamento, medições, faturamento, contas a pagar, programação, conferência ou baixa manual.
- Não substitui fechamento contábil ou BI corporativo.
- Não conecta banco real ou serviços externos.
- Não usa `DELETE` físico.
