# V3.5A - Nota de Entrada e Contas a Pagar Inicial ERP ENAC

## Objetivo

A V3.5A implementa o lancamento local de Nota Fiscal de Entrada vinculada a Pedido de Compra confirmado e a geracao inicial de Conta a Pagar em parcela unica. A etapa fecha o primeiro elo entre compras e financeiro, sem pagamento, sem baixa, sem programacao bancaria real e sem integracao fiscal externa.

## Escopo implementado

- Migration `database/migrations/008_notas_entrada_contas_pagar_mvp.sql`.
- Tabelas `notas_fiscais_entrada` e `notas_fiscais_entrada_itens`.
- Ajuste incremental da tabela `contas_pagar` para o fluxo V3.5A.
- API `GET/POST/PATCH /notas-entrada`.
- API `GET/PATCH /contas-pagar` e `POST /contas-pagar/gerar-da-nota`.
- Telas React `Notas de Entrada` e `Contas a Pagar`.
- Smokes `smoke:notas` e `smoke:contas-pagar`.

## Regras de nota de entrada

- Nota nasce vinculada a um pedido de compra.
- Pedido deve existir e estar no minimo `CONFIRMADO`.
- Pedido `CANCELADO` nao permite nota.
- Fornecedor, obra e centro de custo sao herdados do pedido.
- Itens podem ser herdados dos itens do pedido.
- `numero`, `data_emissao`, `data_entrada` e `valor_total` sao obrigatorios.
- `valor_total` deve ser maior que zero.
- Total da nota deve bater com o total dos itens.
- Nota nao pode ultrapassar valor total do pedido nesta etapa.
- Duplicidade ativa por empresa, fornecedor, numero e serie e bloqueada.
- Nao ha upload de XML.
- Nao ha consulta SEFAZ, prefeitura, NF-e ou NFS-e.

Status controlados:

```text
RASCUNHO
LANCADA
CONFERIDA
APROVADA_FINANCEIRO
CANCELADA
```

Transicoes:

```text
RASCUNHO -> LANCADA
LANCADA -> CONFERIDA
CONFERIDA -> APROVADA_FINANCEIRO
RASCUNHO | LANCADA | CONFERIDA -> CANCELADA
```

## Regras de conta a pagar

- Conta nasce de uma nota de entrada `APROVADA_FINANCEIRO`.
- Empresa, fornecedor, pedido, obra, centro de custo, numero do documento, valor e emissao sao herdados da nota.
- V3.5A permite apenas parcela unica.
- `data_vencimento` e obrigatoria.
- `valor_aberto` inicia igual a `valor_original`.
- Duplicidade ativa por nota e parcela retorna `409`.
- Nao ha programacao bancaria real.
- Nao ha pagamento.
- Nao ha baixa.
- Nao ha conciliacao.

Status controlados:

```text
ABERTA
AGUARDANDO_PROGRAMACAO
PROGRAMADA
CANCELADA
BAIXADA
```

Operacionalmente, a V3.5A usa apenas:

```text
ABERTA
AGUARDANDO_PROGRAMACAO
CANCELADA
```

Transicoes:

```text
ABERTA -> AGUARDANDO_PROGRAMACAO
ABERTA -> CANCELADA
AGUARDANDO_PROGRAMACAO -> CANCELADA
```

## Endpoints

Notas:

```text
GET    /notas-entrada
GET    /notas-entrada/:id
POST   /notas-entrada
PATCH  /notas-entrada/:id
PATCH  /notas-entrada/:id/lancar
PATCH  /notas-entrada/:id/conferir
PATCH  /notas-entrada/:id/aprovar-financeiro
PATCH  /notas-entrada/:id/cancelar
```

Contas a pagar:

```text
GET    /contas-pagar
GET    /contas-pagar/:id
POST   /contas-pagar/gerar-da-nota
PATCH  /contas-pagar/:id
PATCH  /contas-pagar/:id/enviar-programacao
PATCH  /contas-pagar/:id/cancelar
```

## Smokes

```powershell
cd server
npm.cmd run smoke:notas
npm.cmd run smoke:contas-pagar
```

Os smokes usam marcador `DEV_LOCAL_V3_5A`, criam dados locais e nao executam `DELETE`, pagamento, baixa, conciliacao, SharePoint, Entra, automacao ou integracao fiscal real.
