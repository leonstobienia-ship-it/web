## Como rodar seed de homologacao

```powershell
cd "C:\Users\leon\OneDrive - enac.com.br\Documentos\Sistema ENAC\server"
npm.cmd run seed:homologacao
```

O resultado esperado deve mencionar:

```text
DEV_LOCAL_HOMOLOGACAO_ENAC_V316
```

A seed e idempotente e cria massa local para navegacao e validacao. A baixa manual existente na massa e simulada e controlada para homologacao; ela nao representa pagamento real nem liquidacao bancaria.

## Criterios de aceite

- O ambiente local abre sem erro.
- `/health` e `/health/db` retornam OK.
- `seed:homologacao` passa.
- `smoke:homologacao` passa.
- Cada perfil consegue navegar pelos modulos previstos.
- Os dados com marker `DEV_LOCAL_HOMOLOGACAO_ENAC_V316` aparecem na tela Homologacao.
- Dashboard, Previsto x Realizado, Central de Tarefas, Riscos e Documentos retornam dados.
- Nenhum usuario encontra botao funcional de pagamento real, CNAB, banco real, NFS-e real, prefeitura, boleto real, upload externo ou automacao real.
- Feedback foi registrado com severidade, prioridade, evidencia e decisao.

## Criterios de bloqueio

- API ou banco local indisponivel.
- Seed nao executa.
- Smoke de homologacao falha.
- Tela principal nao abre.
- Um perfil nao consegue acessar o modulo central do roteiro.
- Dado critico divergente impede julgamento operacional.
- Qualquer acao funcional proibida aparece: pagamento real, CNAB, banco real, NFS-e real, prefeitura, boleto real, SharePoint real, Graph real, Entra real, Power Automate real, upload externo ou `DELETE` fisico.

## Como registrar feedback

Usar o modelo documentado em `docs/erp/modelo-feedback-homologacao.md`.

Cada apontamento deve ter:

- perfil;
- usuario avaliador;
- modulo e tela;
- tipo;
- severidade;
- prioridade;
- descricao;
- passo a passo;
- resultado esperado;
- resultado obtido;
- evidencia;
- impacto operacional;
- decisao;
- responsavel;
- versao alvo;
- status.

## Como classificar severidade

| Severidade | Criterio |
| --- | --- |
| BAIXA | Ajuste de texto, duvida, detalhe visual sem impacto no fluxo |
| MEDIA | Incomodo operacional ou dado secundario incorreto com contorno simples |
| ALTA | Fluxo importante bloqueado para um perfil ou regra operacional ambigua |
| CRITICA | Risco financeiro, fiscal, permissao indevida, dado essencial incorreto ou acao proibida disponivel |

## Como consolidar backlog da V3.18

1. Agrupar feedbacks por modulo.
2. Separar BUG, REGRA, UX, DADO, PERFORMANCE e SEGURANCA.
3. Marcar itens CRITICOS e ALTOS primeiro.
4. Confirmar decisao: corrigir, ajustar regra, treinamento, postergar ou descartar.
5. Definir responsavel e versao alvo.
6. Abrir V3.18 somente apos a reuniao de consolidacao.
