# V2.7A.2C - Correcao Da Execucao De Status

Data: 2026-06-08

Branch: `dev/v2.3-sharepoint-integracao`

## Diagnostico

A V2.7A.2B corrigiu a leitura do item 11. Em teste manual, a pre-validacao especifica passou com:

- item `11`;
- marcador `V2.7A-TESTE` confirmado;
- status `Recebida`;
- destino `Aguardando aprovação`;
- campo `StatusdaRequisi_x00e7__x00e3_o`;
- `pode executar = sim`.

Ao clicar no botao, a camada de execucao retornou bloqueio generico de atualizacao de requisicao.

## Causa Tecnica

A interface chamava o metodo generico `atualizarRequisicaoCompraControlada()`. Esse metodo revalidava a acao por outro caminho e podia bloquear `AtualizarStatusRequisicao`, mesmo apos a pre-validacao especifica aprovada.

## Correcao Aplicada

Foi criado o metodo especifico:

`executarAtualizacaoStatusRequisicaoV27A()`

Esse metodo:

- revalida o item por GET imediatamente antes da escrita;
- exige `AtualizarStatusRequisicao`;
- exige item configurado igual ao item validado;
- exige marcador `V2.7A-TESTE` confirmado;
- exige status origem `Recebida` ou `Aberta`;
- exige status destino `Aguardando aprovação`;
- exige campo `StatusdaRequisi_x00e7__x00e3_o`;
- executa `MERGE` apenas no item configurado;
- altera somente `StatusdaRequisi_x00e7__x00e3_o`;
- registra historico operacional do teste;
- nao cria pedido, NF, pagamento ou snapshot.

A permissao para `AtualizarStatusRequisicao` foi alinhada para aceitar Diretoria em modo restrito de teste, alem das permissoes operacionais ja existentes.

## Bloqueios Especificos

Quando bloquear, a execucao deve indicar codigos especificos:

- `EXECUCAO_SEM_PREVALIDACAO_ESPECIFICA`;
- `EXECUCAO_ITEM_DIVERGENTE`;
- `EXECUCAO_ACAO_NAO_SUPORTADA`;
- `EXECUCAO_STATUS_ORIGEM_INVALIDO`;
- `EXECUCAO_STATUS_DESTINO_INVALIDO`;
- `EXECUCAO_MARCADOR_NAO_CONFIRMADO`;
- `EXECUCAO_CONFIRMACAO_FINAL_INVALIDA`;
- `EXECUCAO_PERFIL_SEM_PERMISSAO`;
- `EXECUCAO_CAMPO_STATUS_INVALIDO`;
- `ERRO_MERGE_STATUS_REQUISICAO`;
- `HISTORICO_OPERACIONAL_FALHOU`.

## Interface

O painel administrativo continua discreto. O botao so aparece com pre-validacao especifica aprovada e confirmacao final exata.

Apos o clique, o painel deve exibir:

- sucesso ou bloqueio;
- item alterado;
- campo alterado;
- valor anterior;
- valor novo;
- historico criado;
- HTTP da escrita;
- alertas.
