# V3.2 - Fundacao Operacional ERP ENAC

## Objetivo

Criar a base tecnica real para evoluir o Sistema ENAC de blueprint para ERP operacional, preparando React, Node.js, PostgreSQL, Entra ID e SharePoint documental sem quebrar a V3.1 e sem executar operacoes reais no tenant.

## Backend

O backend V3.2 usa Node.js nativo, TypeScript e roteamento HTTP simples. O objetivo e validar a separacao da API antes de introduzir framework, ORM, autenticacao real ou conexao obrigatoria com PostgreSQL.

Endpoint implementado:

```http
GET /health
```

Contrato esperado:

```json
{
  "status": "ok",
  "service": "enac-erp-api",
  "timestamp": "ISO-8601",
  "environment": "development"
}
```

O retorno tambem informa se `DATABASE_URL` esta configurada, mas a V3.2 nao conecta automaticamente em banco real.

## PostgreSQL

A migration inicial cria as tabelas centrais:

- empresas
- usuarios
- perfis
- clientes
- fornecedores
- obras
- centros_custo
- contratos_cliente
- contratos_fornecedor
- solicitacoes_compra
- cotacoes
- pedidos_compra
- notas_fiscais
- contas_pagar
- contas_receber
- medicoes_obra
- documentos

Regras aplicadas:

- UUID como chave primaria.
- Colunas de auditoria nas tabelas principais.
- `company_id`, `obra_id` e `centro_custo_id` onde fazem sentido.
- Sem execucao em producao.
